# Prototype Laboratory

Закрытая лаборатория для прототипирования игровых идей и проверки механик.  
Этот репозиторий не является проектом игры и не содержит финального кода.  
Здесь создаются, хранятся и архивируются прототипы.

---

## Назначение репозитория

Prototype Laboratory используется для:
- проверки игровых идей, ощущений и поведения систем;
- прототипирования механик (fan → loop → core);
- накопления архива прототипов для анализа и сравнения;
- тестирования рабочего процесса и взаимодействия с людьми.

Это рабочая лаборатория, а не продукт.

---

## Общие принципы

- Один прототип = один отдельный Godot-проект.
- Прототипы не объединяются и не мерджатся друг в друга.
- Код пишется только для проверки идеи, без оптимизации и полировки.
- Проверку результата выполняет только владелец репозитория.

---

## Структура репозитория

├── archive/        # Архив завершённых прототипов  
├── README.md       # Этот файл  

---

## Архив (archive)

- Все принятые прототипы попадают в archive.
- Каждый прототип хранится отдельной папкой.
- Если прототип развивается (fan → loop → core) — создаётся новая копия проекта с новым именем.
- История версий сохраняется через Git.

---

## Как начать работу

1. Клонируй репозиторий.
2. Создай ветку от main:  
   work/<username>
3. Работай только в своей ветке.
4. Создай новый Godot-проект с нуля.
5. Размещай проект в папке внутри своей ветки (не в main).

---

## Работа с ветками

- main — пустая базовая ветка.
- work/<username> — рабочая ветка участника.
- archive — ветка архива принятых прототипов.

Правила:
- Ветка work/<username> живёт, пока идёт работа.
- Ветка не мерджится в main.
- Завершённая работа отправляется Pull Request’ом в archive.
- После завершения работы ветка может быть удалена или сохранена по ситуации.

---

## Задачи и управление работой

- Все задачи находятся только в GitHub Issues.
- Задачи выдаются в виде конкретных прототипов.
- Выбор задач и приоритеты определяются владельцем репозитория.
- Коммуникация вне GitHub используется только при необходимости.

---

## Сдача результата

Минимальные требования:
- Рабочий прототип, который запускается.
- Pull Request из work/<username> в archive.

Не требуется:
- описание того, что проверялось;
- отчёты, выводы или анализ;
- самооценка результата.

Любые комментарии, мысли или пояснения — по желанию.

---

## Важно

- Этот репозиторий не про игру, а про проверку идей.
- Здесь нет партнёрства и соавторства.
- Участие добровольное и без обязательств.
- Формат может изменяться по мере развития процесса.

---

## Завершение работы

- Прототип принят — он остаётся в архиве.
- Формат не подошёл — работа прекращается без конфликтов.
- Хорошее совпадение по процессу — возможно дальнейшее сотрудничество.

Это лаборатория.  
Здесь проверяют идеи, а не обещают результат.
